# 数据格式与上传

拟合页面的所有数据入口都汇成同一份**频域复阻抗测量表**：第 $i$ 个数据点为频率 $f_i$ 与复阻抗 $Z_i = \mathrm{Re}_i + j\,\mathrm{Im}_i$。

## CSV 格式（网站标准）

每行 3 个逗号分隔的数，无表头：

```csv
100,52.3,-0.62
200,52.4,-1.25
500,52.9,-3.11
1000,54.8,-6.24
```

| 列 | 含义 | 单位 | 约束 |
|---|---|---|---|
| 1 | 采样频率 $f$ | Hz | > 0，有限 |
| 2 | 阻抗实部 $\mathrm{Re}(Z)$ | Ω | 有限 |
| 3 | 阻抗虚部 $\mathrm{Im}(Z)$ | Ω | 有限 |

解析器同时宽容接受：分号/空白分隔、`#` 注释行、空行、非数值表头行（自动跳过并提示），以及 AlgorithmLcr 的 `measurements.txt` 格式（首行为点数 $n$，字段空白分隔）——实验室旧文件可直接拖入。

## 四种数据入口

1. **上传 CSV / 拖拽**：标准格式，见上。
2. **生成示例**：本地合成一个已知 RLC 网络的阻抗（可调噪声），用于试用与教学。
3. **从历史扫描导入**：选择本站 ESP32 扫描流程已算好的 $f / Z$ 数据，测量与拟合两半直接连通。
4. **ESP32 蓝牙导入**：🚧 **规划中，稍后提供**（Web Bluetooth 直连 ESP32 接收测量文件）。当前页面保留入口按钮并标注"稍后"。

## 数据质量建议

- **点数**：至少 4 点，建议 ≥ 20；对数分布覆盖感兴趣频段；
- **频段**：建议 10 Hz – 10 MHz（三个引擎的示例库与归一化均按此标定）；
- **频点数 vs 参数数**：Try 3 要求频点数 ≥ max(4 × 储能元件数, 2 × 参数数)；
- **噪声**：相对噪声 σ ≤ 2% 时各引擎验证战役的参数误差中位数 < 0.5%；
- **量纲**：全部 SI（Hz / Ω），无 kΩ、mH 之类的前缀——前缀写法只在 Try 2 的元件输入框里支持（`1k`、`100n` 等）。

## 导出

数据面板右上角「导出 CSV」把当前数据（含排序与精度）导出为标准格式，配合 AlgorithmLcr 的命令行工具（`demo --measurements ...`）复算。
